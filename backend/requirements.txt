# The shared package. It lives only in CodeArtifact (domain `webbpulse`,
# repository `python`, us-west-2), not on PyPI, so anything that installs this
# file needs a CodeArtifact token: CI gets one through the org reusable
# workflow, and `deploy-backend.yml` logs in before it builds.
#
# Extras, and why each one: `fastapi` for `create_app` and `run_uvicorn`,
# `dynamodb` for the secret loader and the repository base, `otel` for
# `configure_tracing`, and `aws-otel` for the SigV4-signing exporter that the
# CloudWatch X-Ray OTLP endpoint requires. Without `aws-otel` the package falls
# back to an unsigned exporter, whose 403s the OTLP exporter retries in silence,
# so the failure looks exactly like having no traffic. `testing` is a dev
# dependency and is in requirements-dev.txt.
#
# `security` is new in 0.5.0 and brings PyJWT and bcrypt, which is why neither
# is pinned below any more. `app/core/security.py` is now an adapter over
# `webbpulse.security` rather than its own implementation, and `python-jose`
# left with it: the package signs and verifies with PyJWT. An HS256 token is
# interchangeable between the two libraries and the bcrypt cost is unchanged at
# 12, so no session is invalidated and no stored hash is rewritten.
# `tests/test_security_compat.py` pins both against fixtures minted by the old
# code path.
#
# `identity` is new in 0.6.0 and brings PyJWT[crypto] and fastapi, for
# `webbpulse.identity`: the KMS signer, the JWK encoding and the `.well-known`
# router that the identity standard's M0 spike serves. It is deliberately not a
# dev-only extra even though the spike is throwaway, because the code that
# imports it runs in the deployed identity function.
#
# It does not bring boto3. The module takes a KMS client rather than
# constructing one, so the caller owns that dependency, and boto3 is already
# here through `dynamodb`.
#
# 0.7.0 adds `webbpulse.log_context` and `webbpulse.metrics`, both standard
# library only and both in the base install, so neither is a new extra.
# `log_context` is what removed `aws-lambda-powertools` from the line below it.
# Powertools' correlation is `@logger.inject_lambda_context`, a decorator on a
# Lambda handler, and there is no handler here: the Web Adapter turns each
# invoke into an HTTP request against a uvicorn process, so the decorator never
# ran and every log line carried no correlation id. `RequestIdMiddleware` binds
# a ContextVar instead and `JsonFormatter` merges it, which is the same
# correlation actually reaching the log group. Nothing else imported Powertools.
#
# 0.8.0 is adoption ergonomics and is additive: nothing changes for a caller
# that passes no new argument. What this backend takes from it is
# `webbpulse.http.user_id_dependency`, which fixes the sync dependency trap that
# PR 153 worked around locally by making `get_current_user` `async def` and
# calling `set_user_id` inside it. The binding is the package's now, so the
# resolver goes back to being only a resolver. The other two additions,
# `configure_logging(stream=, formatter=)` and `metrics_enabled_from_env`, are
# not adopted: this backend has no local logging wrapper overriding either of
# those and emits no metrics at all, so there is nothing here for them to
# replace.
#
# 0.9.0 is identity milestone M1, and it is additive in the strict sense: the
# only entry in its Changed section is that `src/webbpulse/identity.py` became
# `src/webbpulse/identity/tokens.py` with `webbpulse.identity` re-exporting the
# entire M0 surface, so `identity_router` and `public_jwk_from_kms`, the two
# names the M0 spike wiring imports, are importable from exactly where they
# were. Nothing in this repository changed to take the bump: the full suite
# passes against 0.9.0 with no source edit, which is the check that the
# re-export claim holds rather than a claim about it.
#
# What the bump makes available, and what PR B mounts, is the rest of M1:
# `IdentitySettings` as a validated `BaseSettings` on the `IDENTITY_` prefix,
# `IdentityHooks`, the storage interfaces, `TokenService` with rotation across
# several keys, `authorizer_claims()` for reading what the gateway authorizer
# leaves on the request, and `build_identity_router`, which serves the two
# `.well-known` documents and `/health` with the Cache-Control headers the
# standard's section 3.4 specifies. The `identity` extra is unchanged at
# `PyJWT[crypto]` and `fastapi`, so this line gains no dependency.
#
# 0.10.0 is identity milestone M2: the password and session flows, plus the
# progressive lockout and the password policy behind them. Additive for a
# consumer that mounts only the documents, and this one no longer is: PR B
# supplies hooks and a credential store, so the six POST flow routes mount.
#
# One breaking change matters here, and it is the one this repository reported.
# Every route now mounts under the issuer's path, derived inside the package by
# `identity_prefix(settings)`, rather than at the origin. 0.9.0 served the two
# `.well-known` documents at the origin whatever the issuer said, and the
# workaround was to mount the router with `prefix="/api/auth"` in
# `app/composition/wiring.py`. That prefix is removed in this change, because
# leaving it would double every route to `/api/auth/api/auth/...`. The
# `identity_mount_prefix` helper that computed it is gone with it: the package
# derives the prefix now, so a second implementation here could only disagree.
#
# `cookie_path` also defaults to the issuer's path rather than a literal
# `/api/auth`, which needs no change here: the issuer already carries that path,
# so the derived value is the one this product was going to set by hand.
